# 0.1.0-alpha.16 — private network discovery subscriptions

Evaluation prerelease; not a stable production release or a completed migration.

- Each parent/owner can enable their own private Telegram discovery alerts.
  A reviewed initial baseline prevents existing devices from causing a startup flood.
- RU/UK/EN card and exact private `/network_alerts on` / `/network_alerts off`
  commands. Freshness, source, member revision and private recipient are rechecked.
- Durable bounded discovery markers, quiet-hour accumulation, configurable
  batching and dispatch pacing. Uncertain delivery is not blindly retried.
- Source replacement cannot silently reactivate old consent when switched back.
  Capacity exhaustion pauses discovery until an explicit new-baseline review.
- Actual-card tests cover stale controls and exact response-loss retries;
  real-HA coverage uses an isolated synthetic Telegram transport.

This is observation, not network intrusion detection or an online-status sensor.
It never changes DHCP, Wi-Fi, firewall or Kid Control rules. Quarantine and strict
enforcement remain pending. A queued alert expires after one hour; it is not
automatically re-created after expiry or uncertain transport.

Guide: [English / Русский / Українська](../network-watch.md).
No household settings, credentials or production actions are included.
