# 0.1.0-alpha.17 — optional purchase price history

Evaluation prerelease, not completion of the full vision or a production migration.

- Shopping card: optionally record the total paid for the quantity bought now.
  RU/UK/EN controls accept exact decimal text and show the shared-family disclosure.
- Each purchase event retains its own total, currency, item and store snapshot.
  Free purchases are explicit zero; unpriced purchases stay unpriced. No guessed
  unit costs, automatic shop access, currency conversion or historical backfill.
- Strict server-side validation and existing approval/role boundaries remain.
  Exact lost-response retry survives an unrelated pending command; stale identity,
  module, item and detached controls cannot submit a retained draft.
- Developer-only native CHR testing now detects one-way FastTrack leakage, not
  just failed round trips. Mitigation was tested only on fixture-owned rules and
  selected synthetic connections. No new runtime firewall enforcement is claimed.

Guide: [English / Русский / Українська](../shopping.md).
All active family members can read shopping price history. It is not private
accounting. The integration does not purchase goods or spend money.

Existing HA Store data stays outside the HACS-managed component directory. Take
the normal verified HA backup before upgrading. Do not overwrite a newer Store
with an older snapshot merely to downgrade code. No household data or credentials
are part of this release, and no production installation is changed by publishing it.
