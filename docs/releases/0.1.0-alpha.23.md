# 0.1.0-alpha.23 — verified fresh-entry shadow staging

Evaluation prerelease. This is an internal migration building block, not an
enabled public migration wizard or permission to replace an existing household.

- Reconstruct a whole read-only candidate from its original private source archive,
  pinned members/reviewer sets and freshly decoded historical photo evidence.
  Reject changed projections, summaries, targets and blob sets.
- Stage only a new unregistered entry, authorized by its currently bound active
  administrator-owner. Refuse existing entries, foreign state/intent/directories
  and backup conflicts. No source or live household is overwritten.
- Write an immutable native HA Store intent, publish verified private blobs without
  overwrite, then commit the copy's Store last. Exact retries handle a lost write
  acknowledgement; cancellation settles owned writes before releasing coordination.
- Native HA acceptance uses this staging path, including a simulated lost response
  after an actual Store commit, then separately registers the synthetic entry to
  test first setup, private photo access, zero entities/workers and reload.

No automatic ConfigEntry creation/activation, source cutover or residue deletion.
Unknown/damaged temporary files require review; arbitrary power-loss recovery is
not claimed. [Three-language contract and limitations](../legacy-shadow-staging.md).
