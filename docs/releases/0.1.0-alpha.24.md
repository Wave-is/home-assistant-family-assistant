# 0.1.0-alpha.24 — sealed read-only entry registration

Evaluation prerelease; this is not the public migration wizard or household cutover.

- A migration entry carries an independent read-only seal in Core's ConfigEntry
  data. Setup checks the exact full Store fingerprint and owner binding before
  creating a runtime. A missing/changed Store or seal cannot create a blank,
  writable replacement family. Ordinary fresh setup remains unchanged.
- Internal reviewed registration stages verified data, then uses Core's native
  ConfigEntry creation API. Exact same-ID retries recognize a registered copy;
  they do not overwrite another entry or create a second one after a lost reply.
- Active administrator-owner authority is checked again after waits. Cancellation
  drains an owned Core registration before releasing its lock. The receipt says
  separately whether the registered read-only viewer is actually loaded; an
  unloaded/retrying entry is not force-started.
- Synthetic native HA tests exercise a lost acknowledgement after actual Core
  registration, exact retry, child denial, private historical photos, missing or
  changed Store loads, restoration of exact original bytes, and zero workers.

No legacy installation was replaced. No migration endpoint/ConfigFlow, activation,
residue deletion or universal power-loss recovery is claimed. Private source
capture, member/photo matching, owner review and controlled cutover remain gates.
See the [three-language contract](../legacy-shadow-registration.md).
