# 0.1.0-alpha.28 — owner-reviewed technical diagnostics

Evaluation prerelease, not completion of the full vision or a production cutover.

- Optional, off-default owner consent for future queued Telegram model failures.
  Bounded, allowlisted technical categories and counts share the existing atomic
  job-completion/outbox write. A failed write retries without double counting or
  a second model request. Successes and stale/cancelled jobs are not collected.
- No message/quote/answer content, names, IDs, URLs, exact times, private hashes,
  provider settings or arbitrary health details enter the report. Invalid stored
  diagnostics are preserved and skipped, without blocking ordinary bot completion.
- EN/RU/UK native Options and Health card explain consent, retained earlier counts
  and limitations. Owner preview shows the entire JSON before a local download;
  fresh server authority and generation checks reject a stale review. No automatic
  telemetry, issue submission, agent execution or code installation.
- Exact consent retries handle failed storage and lost committed responses without
  overriding a later opt-out. In-flight jobs cannot cross disable/re-enable epochs.
- Actual isolated HA passed native consent, synthetic Telegram model timeout,
  first-commit storage failure, one reply/one count, authenticated report and full
  Store reload. Native full-suite denial tests now drain their fixture scheduler
  before comparing the whole Store; authorization assertions remain unchanged.

Technical observations are not semantic reproducers: they cannot explain why a
particular sentence was misunderstood. The developer-side patch proposal queue and
semantic feedback path remain unfinished. Live household settings are unchanged.
