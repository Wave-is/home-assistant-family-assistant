# 0.1.0-alpha.34 — reviewed existing Home Assistant agent

Evaluation prerelease, not full-vision completion or household cutover.

- Optional preferred provider using the official native Ollama conversation
  entity on Core **2026.8.2 only**. Default instructions and no Home Assistant
  control/LLM API are required; other native agents/versions are rejected.
- Declared optional native dependency for safe imports and startup ordering;
  other modules do not require an Ollama configuration entry or model server.
- Owner-only EN/RU/UK selection and separate confirmation persist exact native
  entry/subentry bindings. No model call during setup, and no native credentials
  copied. Direct primary/fallback Ollama settings remain independent and intact.
- Real caller identity, fresh native conversations, role-filtered family input,
  strict JSON and unchanged proposal/confirmation authorization. Unlinked users
  may use configured direct providers; identity revocation never borrows owner
  privileges or bypasses denial through a fallback.
- Target, client, settings and user authority are rechecked around asynchronous
  calls. New native agents' unknown last-activity timestamps are supported.
  Native-only inference does not construct an unrelated HTTP/DNS client.
- Native acceptance exercises the actual Ollama entity and stream parser with
  a synthetic transport: no control tools, child identity/privacy, malformed
  output, unsolicited tool calls, Store/reload and disabling the selection.

No household bot, model server, router or production Home Assistant was changed.
