# Family Assistant 0.1.0-alpha.9

Development prerelease for isolated evaluation; household cutover is not complete.

- Repeated text reports retain the previous report, feedback, submission time and
  assignee identity. A corrected report no longer displays the previous rejection
  note. Disk failure and exact retry do not erase or duplicate history.
- Parents can expand and page through textual report history in RU/UK/EN Tasks
  cards. Children do not receive previous report history. Changed identity or
  stale task data revokes an already rendered history pager.
- Read-only legacy conversion now reconstructs text reports from explicit
  submission/review events, preserving old empty reports and separate terminal
  notes. It never guesses that `last_note` means the report body. Reviewer mappings
  require current parent/owner authority and an explicit parent-review policy.

Photo migration, reassignment history, nonparent legacy reviewers, coherent source
capture, complete shadow import and controlled live cutover remain unfinished.
No migration apply endpoint or automatic production update is introduced.

See the [migration contract](https://github.com/Wave-is/home-assistant-family-assistant/blob/0.1.0-alpha.9/docs/legacy-migration.md)
and [requirement matrix](https://github.com/Wave-is/home-assistant-family-assistant/blob/0.1.0-alpha.9/docs/implementation-status.md).
