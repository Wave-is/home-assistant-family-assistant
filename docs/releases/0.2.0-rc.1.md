# 0.2.0-rc.1 — control-center and legacy workflow repair

Release candidate, not a claim that the entire product vision or every live
household migration is finished. Promotion awaits the release gates in
[the acceptance record](../control-center-repair.md).

## Changes

- Replaced demonstration settings with the authorized five-section family panel,
  configurable members, EN/RU/UK copy, persistent setup progress, partial revisioned
  saves, conflict handling, frozen retries and real read-back.
- Fixed duplicate custom-element registration and native HA authenticated-caller
  handling. Changed Options are reauthorized after provider validation.
- Added a complete owner-reviewed Telegram member/group enrollment path. Separate
  polling, delivery and addressed-message observations replace simulated checks.
- Restored deterministic legacy task, shopping and weekday/weekend alarm commands.
  Added verified one-photo task reports and persistent media processing without
  model dependency; unknown/ambiguous targets do not trigger actions.
- Repaired configured court identities, periods, atomic awards and reversible
  source penalties. Added optional reporting thresholds with no automatic effects.
- Scoped member school/alarm settings; private recipient settings do not impersonate
  another family member. Module switches reconcile configured runtimes without
  restarting the bot. Disabled imported schedules are reported explicitly.
- Preserved modern profiles and linked identities through reviewed shadow copies;
  fixed image-job isolation, model quota cooldown and unsupported-image handling.
- Removed household demonstration artifacts and an unreviewed environment-specific
  gateway from publishable source. Runtime remains a single HA integration.

## Compatibility and remaining limits

Family Store and Config Entry Options stay separate from HACS-managed code.
Updates preserve unknown settings, existing device mappings and entity choices.
New personal court-score sensors are disabled by default because HA entity states
do not inherit the private panel's member permissions.

Imported alarms remain disabled/gentle/penalty-free until reviewed activation.
No siren, punishment rule, household router or provider credential is automatically
enabled by installation. Physical delivery/audibility needs separate acceptance.
Telegram voice/STT, generic home/energy control mappings and durable scoped
conversational memory are not supplied by this candidate. Technical provider
configuration still uses native Options; deterministic preview is not an LLM test.

## Update and rollback

Back up the exact current integration code and HA configuration before installing.
Validate configuration, then use the required reviewed HA restart. Do not copy
sanitized snapshots, raw Store internals or household demo data into production.
For a code rollback, restore the captured prior runtime directory and restart
through the same approval procedure; preserve Store/Options and verify current
tasks, identities, schedules, settings and transport health. New optional features
may not be visible to older code. Full backup restore is a separate operation,
not an automatic rollback step.
