# 0.2.0-rc.7 — shared purchase assignments and durable school settings

**Pre-release / Ранняя версия / Рання версія.**

- Explicit numbered Telegram requests create 2–5 tasks atomically. Every item,
  recipient, deadline and report requirement is validated before committing;
  retry/restart preserves original dates and IDs. See [grammar](../telegram-task-batches.md).
- Assign a responsible buyer with `ask MEMBER to buy ITEM`, change or clear that
  assignment by item ID, and filter the dashboard or Telegram list. The list
  stays shared and other family members may help buy. Narrow independently
  verified name-typo learning now also covers assigned purchases; it does not
  change identity or permissions. See [purchase commands](../shopping-assignments.md).
- Existing school settings preserve selected student, reminder switches, time
  and recipients. Verified policy-only edits work offline and retain cached
  facts and homework acknowledgements. Stale queued notices are revoked without
  repeating the day's preparation message. An explicit refresh discovers other
  students. Account/identity changes still require discovery and a new generation.
  See [school editing](../school-options-editing.md).

## Обновление / Оновлення / Upgrade

Back up HA, select this prerelease in HACS, restart Core through the supported
procedure and refresh the browser. Config Entry Options and family Store remain
outside the component. No new school notifications, alarms, network rules or
physical device actions are enabled by the update.

Сделайте резервную копию, обновитесь через HACS, перезапустите Core и обновите
страницу. Назначение покупателя не делает список личным. Обычное изменение
школьных уведомлений теперь сохраняет кэш и отметки выполненного ДЗ.

Зробіть резервну копію, оновіться через HACS, перезапустіть Core та оновіть

сповіщень зберігає кеш та позначки виконаного домашнього завдання.

## Rollback and limits

Use [rollback](../rollback.md) and retain Store/Options/receipts. Returning to
rc.6 removes the new grammar and restores its school-edit limitations; it does
not restore past family data. Do not edit `.storage` or replay uncertain saves.
Turning school notifications off/on differs from re-enabling a disabled account:
the latter rediscovers and resets the source generation. Newly added recipients
receive future notices, not another copy of an already-consumed daily notice.

Arbitrary inline multi-task prose, daily rollover/corrections, scoped conversation
memory/media, household control/energy mappings and other [legacy gaps](../legacy-parity-audit.md)
remain open. Physical siren/router acceptance, real nonempty school grades/files
and HACS default-catalog admission are separate gates. This is not completion of
the whole vision. Exact final combined test and CI results belong to the release
checkpoint; implementation alone does not establish those results.
