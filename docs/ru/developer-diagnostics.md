# Технический отчёт для разработчика

По умолчанию сбор выключен. Владелец включает его в **Настроить → Диагностика
для разработчика**. Учитываются только новые запросы Telegram к модели,
завершившиеся технической ошибкой. Успешные, отменённые и устаревшие запросы,
обычные команды, разговор с дашборда/Assist, доставка и polling сюда не входят.

В карточке состояния выберите **Проверить технический отчёт**, прочитайте весь
JSON и при желании нажмите **Скачать проверенный JSON**. Перед скачиванием
повторно проверяются права, версия согласия и точное содержимое. Если отчёт
изменился, его нужно просмотреть заново. Отправлять файл разработчику или нет —
решаете вы: автоматической отправки и создания GitHub issue нет.

В файле только публичная версия модуля, фиксированные коды технических ошибок,
признаки наличия цитаты/ссылок на записи и ограниченные счётчики. Нет переписки,
имён, ID, точного времени, адресов провайдеров, секретов или хешей приватных данных.
Неизвестная ошибка становится `other`. Счётчики ограничены 999999, неполнота
помечается. Сейчас возможны 36 категорий при защитном лимите 64.

Выключение сохраняет прежние счётчики, но исключает незавершённые запросы даже
после повторного включения. Повтор потерянного ответа не отменяет позднейший
отказ владельца. Повреждённая запись не затирается; её пропускает сборщик,
не останавливая обычную обработку бота. Данные остаются в приватном HA Store
вне каталога обновляемого кода.

Это не автоматическое исправление и не воспроизведение неправильно понятой
команды. Разработчик сначала воспроизводит сбой на вымышленных данных, добавляет
регрессионный тест, проверяет исправление и выпускает проверенный релиз.
По счётчику таймаутов нельзя выдумывать причину смысловой ошибки. Приватные
экспорты и логи к публичному отчёту не прикладывайте. Модуль не запускает
консольных агентов, не передаёт доступы к дому и не применяет сгенерированные патчи.
Автоматизированная очередь предложений разработчику и смысловая обратная связь
ещё не реализованы.
