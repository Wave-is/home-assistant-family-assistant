# Настройка семьи

[English](setup.en.md) · [Українська](setup.uk.md)

Инструкция для разработки. **Тестовый предварительный релиз опубликован; стабильного пока нет.** Проверяйте
модуль в отдельном HA, не заменяя действующую семейную систему. Реальное
состояние функций указано в [матрице готовности](implementation-status.md).

[Голосовые покупки через Assist](voice-shopping.md#русский): настройка,
подтверждение голосом и права учётной записи. Голосовые сообщения Telegram пока не поддерживаются.

## Установка и участники

Путь установки релиза: HACS → Пользовательские репозитории →
`Wave-is/home-assistant-family-assistant`, категория «Интеграция». Выберите
проверенный релиз, установите и перезапустите HA по запросу. Затем Настройки →
Устройства и службы → Добавить интеграцию → Family Assistant. Включение в
основной каталог HACS требует отдельного рассмотрения; пока оно не заявлено.

Одно подключение интеграции — одна семья. Создаёт её администратор HA: название,
своё имя, язык, часовой пояс IANA, например `Europe/Kyiv`, и шаблон. Остальные
участники шаблона — редактируемые заготовки без аккаунтов и доступа.

В «Настроить → Добавление или изменение участника» владелец меняет имена, роли, языки и привязывает
пользователей HA. В поле других имён укажите формы имени по одной на строку:
например, именительный и дательный падежи. Одинаковые имена требуют уточнения.
Родители подтверждают задачи; роль «Взрослый» сама по себе не даёт родительских
прав. Ребёнок видит только свои задачи, будильники и баллы.

Данные и секреты хранятся в конфигурации HA и Store вне `custom_components`.
Обновление кода не заменяет их. Резервные копии HA держите приватными. Не
публикуйте `.storage`, токены и логи без проверки и не редактируйте Store вручную.

## Отложить настройку или редактирование профиля

Перед подключением сервисов редактирование семьи или профиля в центре управления
можно отложить кнопкой **Продолжить позже**. Незавершённые поля переживают
обновление той же вкладки; нажмите **Продолжить черновик** для проверки и
продолжения. Для каждой учётной записи и семьи хранится один черновик; при чтении
через 24 часа без изменений он удаляется. Он может содержать личные данные,
поэтому на общем устройстве используйте **Удалить черновик**. Восстановление
сессии браузера может сохранить данные вкладки. Секреты подключений исключены.
При новой серверной версии или уже предпринятой попытке сохранения доступен
только просмотр: проверьте текущие данные семьи и удалите черновик перед новым
редактированием. Черновики не применяют настройки и не включают сервисы.

## Каждый создаёт своего бота

1. Откройте проверенного `@BotFather`, отправьте `/newbot`, задайте имя и
   уникальное имя пользователя с окончанием `bot`. Никому не передавайте токен.
2. Family Assistant → Настроить → Подключить своего Telegram-бота: включите
   подключение и вставьте токен в защищённое поле. При последующем редактировании
   пустое поле сохраняет старый токен. Выключение не удаляет данные семьи.
3. Добавьте бота в домашнюю группу. В HA выберите привязку семейной группы,
   отправьте туда показанную команду `/family_setup@ваш_бот КОД`.
4. Продолжите форму ожидания, проверьте найденные название и ID, подтвердите в
   HA. Само получение кода ещё не даёт доступа.
5. Для каждого человека откройте привязку личного чата. Именно этот человек
   должен открыть выданную ссылку и нажать «Старт». Проверьте найденный аккаунт
   и подтвердите в HA. Личные чаты родителей нужны и для приватных уведомлений.
6. Напишите в группе `@ваш_бот тут?` или `/ping@ваш_бот`, подставив настоящее
   имя бота. Эта проверка работает без LLM.

Сторонний бот для определения ID не нужен. Telegram не разрешает боту первым
начать личный разговор. Код действует 15 минут; просроченный замените новым.
Не публикуйте ссылки приглашения.

Для команд, упоминаний и ответов оставьте Privacy Mode включённым. Обращаться
можно ответом на сообщение бота. `/setprivacy` в BotFather управляет доставкой
сообщений группы; после отключения приватности может понадобиться повторно
добавить бота. **Получение всех сообщений не включает ответы на весь разговор:**
текущая версия всё равно ждёт прямого обращения.

У одного токена должен быть только один обработчик. Нельзя одновременно
использовать его здесь, в стандартной интеграции Telegram Bot и другой
программе. При конфликте webhook/poller сначала остановите прежний обработчик.
Family Assistant не удаляет webhook чужого приложения.

## Команды без LLM

| Команда | Действие |
| --- | --- |
| `/help`, `/ping` | Справка и быстрая проверка |
| `/shopping` | Отдельный список покупок |
| `/buy Молоко \| 2 \| л` | Добавить товар; заявку ребёнка одобряет родитель |
| `/bought S000001` | Куплен весь оставшийся объём |
| `/tasks` | Доступные задачи |
| `/task Ребёнок 1 \| Собрать рюкзак` | Назначить задачу по имени или псевдониму |
| `/done T000001 \| Всё собрано` | Сдать текстовый отчёт |
| `/approve T000001` | Родитель подтверждает выполнение |
| `/stats` | Баллы и конкретные причины |
| `/alarms` | Расписания подъёма |

Поддерживаются отдельные обычные формулировки: «Ребёнок 1 задача собрать рюкзак,
срок до конца недели». Ответ на подтверждение этой задачи: «установи срок
завтра». Конец недели — воскресенье, время по умолчанию — 20:00 в часовом поясе
семьи. Прошедший срок, неверная дата и неоднозначное время перевода часов не
подставляются молча. Цитата должна ссылаться на реально отправленное ботом
сообщение с сохранённым подтверждением отправки. Копия текста этого не заменяет.

Это ограниченная грамматика, а не обещание понять любую фразу. Непонятный
запрос сам по себе не меняет данные. Скрытого провайдера разработчика нет.

## Модель, резерв и поиск — по желанию

Уже есть разговорный агент HA? Доступна отдельная [настройка готового
агента](ha-conversation-agent.md#русский): пока только штатный агент Ollama без
управления домом в Core 2026.8.2. Прямые подключения ниже остаются независимыми.

1. Включите «Разговор» в общих настройках. В параметрах модели укажите свой
   базовый URL Ollama и точное имя установленной модели (`ollama list` или
   `/api/tags`). Можно отдельно задать резервный сервер и его модель.
2. При сохранении проверяется наличие обеих выбранных моделей. Ошибка,
   тайм-аут или неверный формат ответа переключают запрос на резерв. На эти
   серверы передаются обращения и ограниченные ролью семейные данные. Не
   подключайте недоверенный сервер. Токен бота, аккаунты HA и капча не передаются.
3. Предпочитайте HTTPS или доверенную LAN/VPN. Для HTTP нужно отдельное согласие:
   он не шифрует данные. Не открывайте Ollama напрямую в интернет. Пустое поле
   ключа сохраняет его; при смене адреса нужен новый ключ либо явная очистка.
4. Для интернета настройте свой SearXNG, включив `json` в `search.formats`.
   Модель сама по себе не умеет искать. Пока обрабатываются поисковые выдержки
   с проверенными на внутренние адреса ссылками. Чтение полной открытой статьи
   включается отдельно в настройках чтения статей: проверьте политику доступа
   детей, затем явно подтвердите публичный HTTPS-адрес в разговорной карточке.
   Это не автоматическое чтение ссылок в Telegram; семейный контекст в запрос
   пересказа не передаётся. См. [руководство по статьям](articles.md).
   Другие поисковые адаптеры ещё не реализованы.
5. Непонятное прямое обращение попадает в сохраняемую очередь. `/ping`, обычные
   команды и кнопки подъёма не ждут модель. Цитата — недоверенный контекст, не
   разрешение на действия. Для предложенного изменения бот показывает план:
   подтвердите кнопкой Telegram, `/confirm P…` или на дашборде. `/cancel P…`
   отменяет. План действует пять минут и принадлежит отправителю; права и
   версии записей проверяются заново. Скрытого применения нет.
6. Появляется стандартная разговорная сущность: её можно выбрать в Assist.
   Голосовой терминал без привязанного пользователя не получает права родителя.
   Доступно [подтверждение голосом](voice-shopping.md#русский). Передача обращений
   готовому агенту ограничена отдельно проверенной штатной Ollama без управления
   домом, описанной выше; произвольные агенты не поддерживаются.

Даты рассчитывает код, а найденные страницы не могут вызвать команды.
Недоступность модели не отключает списки, задачи и будильники. Безопасный цикл
подготовки патчей остаётся следующим отдельным этапом.

Научить своей фразе можно явно: `/learn мои покупки | /shopping`. Правило
действует только для вашего аккаунта. В карточке «Разговор» есть форма обучения
и список ваших фраз. `/forgetphrase L…` выключает правило. Оно не расширяет права;
относительная дата и задача из цитаты определяются заново при каждом обращении.
Старые `/forget` и `/забыть` только объясняют различие и ничего не удаляют.
Очистка старой краткосрочной и долгосрочной разговорной памяти не реализована.

Если другой агент HA поддерживает выбор LLM API, ему можно назначить API семьи
Family Assistant: чтение доступных данных и подготовку подтверждаемого плана,
без произвольных служб HA. Анонимный вызов отклоняется. Это доступ агента к
инструментам, а не автоматическая передача ему Telegram-переписки.

## Карточки

В обычном режиме хранения ресурсов Lovelace **storage** Family Assistant
регистрирует один локальный JavaScript-модуль на всю установку HA. Несколько
семейных пространств используют его совместно. Отпечаток содержимого версионирует
весь граф относительных модулей, поэтому после обновления новый код карточки не
смешивается со вспомогательными модулями из длительного кеша браузера. Внешних
загрузок нет. После установки интеграции или обновления через HACS перезапустите
Home Assistant, чтобы зарегистрировались новый отпечаток и статические пути,
затем обновите страницу и добавьте карточку из списка. Визуальный редактор
предлагает только семьи, связанные с вашим аккаунтом, — вручную копировать ID
записи не нужно.

Доступны 17 типов карточек:

- `custom:family-assistant-card` — сегодня;
- `custom:family-shopping-card` — покупки;
- `custom:family-tasks-card` — задачи;
- `custom:family-court-card` — правила и поощрения;
- `custom:family-alarms-card` — будильники;
- `custom:family-health-card` — состояние системы;
- `custom:family-conversation-card` — разговор;
- `custom:family-network-card` — домашняя сеть;
- `custom:family-calendar-card` — календарь;
- `custom:family-routines-card` — рутины;
- `custom:family-pantry-card` — запасы;
- `custom:family-meals-card` — питание;
- `custom:family-school-card` — школа;
- `custom:family-maintenance-card` — обслуживание;
- `custom:family-polls-card` — опросы;
- `custom:family-presence-card` — присутствие;
- `custom:family-digests-card` — дайджесты.

Family Assistant обновляет только storage-ресурс со своей точной меткой
принадлежности. Существующий ручной URL не присваивается и не перезаписывается.
Если HA показывает предупреждение о frontend-ресурсе, следуйте
[инструкции по ресурсам](frontend-resources.md): удалите дубликат вручную перед
перезагрузкой либо оставьте документированную ручную запись, если ресурсы
Lovelace работают в YAML-режиме. Family Assistant не редактирует YAML или
`.storage` напрямую.

Карточка использует язык интерфейса HA, бот — язык участника. Сервер проверяет
права независимо от видимости кнопок.

## MikroTik — необязательный инвентарь

Включите MikroTik в общих параметрах и откройте его подключение. Нужны свой
HTTPS-адрес RouterOS 7 и отдельный аккаунт с `read,rest-api`. У штатной группы
read есть лишние права. При необходимости вставьте доверенный CA-сертификат,
но не приватный ключ; проверка TLS не отключается. Пустое поле сохраняет пароль,
кроме случая смены адреса или пользователя.

На RouterOS **7.20.1** реальный тест выявил дополнительное требование права
`api`: для этой версии нужен набор `read,api,rest-api`. Доступ к службам управления
ограничьте хостом HA; право `api` также разрешает вход через обычный API, если
его порт доступен. Не выдавайте права администратора и не открывайте порты наружу.
Интеграция сама не меняет пользователей роутера, службы или firewall.

Карточка «Домашняя сеть» показывает устройства, текущие комментарии и основания
совпадений с HA. Неоднозначные имена требуют выбора; локально назначенный MAC
не доказывает появление постороннего. Ошибка чтения сохраняет последнее успешное
наблюдение.

Для изменения выбранных лизов владелец отдельно разрешает запись, задаёт и
подтверждает защищённые MAC хоста HA и своего устройства управления. Аккаунту
RouterOS тогда нужно также право `write`. Выберите лизы в карточке, проверьте
предлагаемые комментарии и создайте предпросмотр. Старые комментарии сохраняются
без галочки замены. Применение плана — отдельное действие в течение пяти минут.
Для преобразования нужно также явное согласие на откат: он удаляет только
новую резервацию, а динамический лиз восстанавливается через обновление DHCP;
это не точное восстановление. Карточка различает очередь, проверенный результат,
откат и необходимость ручной проверки. Kid Control, строгий список и проверка
на живом RouterOS имеют отдельные проверки. [Границы сетевого модуля](network-architecture.md).

### Оповещения о новых устройствах и строгий режим

Родители могут подписаться на оповещения о неизвестных устройствах в карточке
домашней сети или через своего Telegram-бота: `/network_alerts on` (и `/network_alerts off`).
Новые устройства пакетируются, чтобы избежать спама, и задерживаются в тихие часы.
Обнаружение открывает активный инцидент. После проверки всех устройств (или добавления
их в план допуска) интеграция отправляет закрывающее подтверждение:
`Все ранее неизвестные устройства проверены. Оповещение о новых устройствах в сети закрыто.`

Строгий сетевой режим (enforcement) невозможно включить без подтверждения аппаратных
предусловий. Владелец записывает свидетельство топологии через
`mikrotik.network_record_strict_evidence`, подтверждая: правила ограничения IPv4 и IPv6,
учёт обхода FastTrack, исключение управляющих хостов и восстановление после перезапуска.
Свидетельство привязано к хешу роутера и действует 30 дней. Карточка сети показывает
доступность строгого режима и коды невыполненных предусловий.
Подробнее: [проверка устройств и строгий режим](network-admission.md).

## Управление интернетом детей

В параметрах подключения отдельно включите запись Kid Control и подтвердите
защищённые MAC Home Assistant и устройства управления. В карточке сети владелец
выбирает существующий профиль RouterOS и ребёнка, проверяет **все устройства**
профиля и подтверждает принадлежность. Это пока только локальная привязка.
Родители могут составлять планы паузы, возврата обычного расписания, временного
доступа/паузы, часов доступа и скорости. Применение требует отдельного подтверждения.
Взрослому без роли родителя владелец выдаёт право отдельно. Ребёнку доступны
только собственный профиль и расписание, без MAC и кнопок управления.

Команды вашего бота: `/internet Ребёнок`, `/netpause Ребёнок`,
`/netresume Ребёнок`, `/netgrant Ребёнок | 30`, `/netblock Ребёнок | 15`,
`/netuntil Ребёнок | 21:30`, `/netschedule Ребёнок | будни | 08:00-22:00`,
`/netlimit Ребёнок | 5M`. Подставьте настроенное имя или псевдоним ребёнка.
Проверьте план, нажмите подтверждение либо `/netconfirm K000001`.
`/netcancel K000001` отменяет ещё не применённый план. Бот сначала ставит работу
в очередь, затем сообщает проверенный результат лично инициатору.

Пауза действует до отмены. Возобновление возвращает расписание, а не круглосуточный
доступ. Для временного режима нужны RouterOS 7.16+, синхронные часы и одинаковые
часовые пояса семьи и роутера. До изменения создаются и проверяются два узких
таймера: окончание вернёт прежний режим даже без HA, перезагрузка роутера завершит
исключение досрочно. Изменённый вручную или пересозданный профиль не перезаписывается.
Оставьте интеграцию подключённой до итоговой проверки и закрытия события.

Сквозную блокировку проверьте на некритичном клиенте: IPv6, FastTrack и другой NAT
могут влиять на результат. Окна `tur-*` имеют приоритет над лимитом скорости;
изменение часов дня очищает его отдельное окно без лимита, что видно в плане.
Тест синтетического профиля не доказывает блокировку всей сети. Создание профилей,
выбор отдельных устройств, каникулы и строгий список ещё в разработке.

## Будильник и доставка

В карточке задач есть **«Добавить регулярную обязанность»**. Выберите людей,
ежедневное/еженедельное/ежемесячное правило, время создания и срок. Каждый
получает отдельную задачу либо участники работают по очереди. Дополнительные
настройки содержат исключения, окончание, интервал, напоминание, паузу после
срока и необязательный штраф. Запуск — со следующего момента по расписанию;
после долгого простоя уже просроченные задачи не создаются. Несуществующие
числа месяца пропускаются. Выключение останавливает новые задачи, сохраняя
старые и историю. Сданный отчёт не штрафуется из-за задержки проверки родителя.
Штраф требует одновременно общего разрешения и отрицательного значения у
задачи/обязанности. Подтверждение выполнения не стирает начисление молча.

Заведите отдельные расписания будней и выходных. Мягкий режим — только
сообщения. Строгий добавляет **отдельную** сирену, назначенную с подтверждением
в настройках интеграции. Не используйте пожарную или охранную сигнализацию.
Громкость проверьте физически: состояние HA не доказывает наличие звука.
Перед тестом карточка спрашивает ещё раз; тест не штрафует.

Первая свежая мини-капча останавливает звук. Через случайные 12–18 минут по
умолчанию приходит вторая; без ответа после разрешённой паузы строгий режим
снова включает звук. Старая кнопка или ответ другого человека не засчитываются.
Автоштрафы изначально выключены и ограничиваются отдельным дневным пределом.

На карточке состояния видны ошибки доставки. Тайм-аут может возникнуть после
принятия сообщения Telegram, поэтому автоматического слепого повтора нет.
Посмотрите чат и либо закройте предупреждение, либо явно подтвердите повтор с
причиной и согласием на возможный дубль. «Ожидается чат» — привяжите получателя.

Перед рабочим использованием проверьте права всех участников, упоминания,
цитаты, повтор команды, сохранение данных после перезапуска и оба этапа
будильника, пока все бодрствуют. До проверки держите автоштрафы выключенными.
Публичный релиз, миграция и проверка устройств — отдельные этапы приёмки.
