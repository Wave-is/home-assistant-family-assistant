# Технічний звіт для розробника

Типово збір вимкнено. Власник вмикає його в **Налаштувати → Діагностика для
розробника**. Враховуються лише нові запити Telegram до моделі, що завершилися
технічною помилкою. Успішні, скасовані та застарілі запити, звичайні команди,
розмова з дашборда/Assist, доставка та polling сюди не входять.

У картці стану виберіть **Перевірити технічний звіт**, прочитайте весь JSON
і за бажанням натисніть **Завантажити перевірений JSON**. Перед завантаженням
знову перевіряються права, версія згоди та точний вміст. Змінений звіт потрібно
переглянути знову. Надсилати файл розробнику чи ні — вирішуєте ви: автоматичного
надсилання та створення GitHub issue немає.

Файл містить лише публічну версію модуля, фіксовані коди технічних помилок,
ознаки наявності цитати/посилань на записи та обмежені лічильники. Немає
листування, імен, ID, точного часу, адрес провайдерів, секретів чи хешів приватних
даних. Невідома помилка стає `other`. Лічильники обмежені 999999, неповнота
позначається. Наразі можливі 36 категорій із захисним лімітом 64.

Вимкнення зберігає попередні лічильники, але виключає незавершені запити навіть
після повторного ввімкнення. Повтор втраченої відповіді не скасовує пізнішу
відмову власника. Пошкоджений запис не перезаписується; збирач його пропускає,
не зупиняючи звичайну обробку бота. Дані залишаються у приватному HA Store
поза каталогом коду, який оновлює HACS.

Це не автоматичне виправлення і не відтворення неправильно зрозумілої команди.
Розробник спочатку відтворює збій на вигаданих даних, додає регресійний тест,
перевіряє виправлення та випускає перевірений реліз. Лічильник таймаутів не
доводить причину змістової помилки. Не додавайте приватні експорти й логи до
публічного звіту. Модуль не запускає консольних агентів, не передає доступи
до дому та не застосовує згенеровані патчі. Автоматизована черга пропозицій
розробнику та змістовний зворотний зв'язок ще не реалізовані.
